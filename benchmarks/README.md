# Kvasir Knowledge Graph Benchmarks

External Python-based benchmark suite for the Kvasir KG. It is split into two
independent scripts so that the expensive data-loading step can be performed
once and the query benchmarks can be iterated quickly without re-loading.

## Prerequisites

```bash
pip install requests python-dotenv
```

Or with a virtual-env / mise:

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install requests python-dotenv
```

## Configuration

Copy `.env.example` to `.env` and fill in the values:

```bash
cp .env.example .env
```

| Variable | Default | Description |
|---|---|---|
| `KVASIR_BASE_URL` | `http://localhost:8080` | Base URL of the Kvasir server |
| `KVASIR_POD_NAME` | `benchmark` | Name of the pod to use (will be created if missing) |
| `KEYCLOAK_URL` | `http://localhost:8280` | Keycloak server URL |
| `KEYCLOAK_REALM` | `kvasir` | Keycloak realm name |
| `CLIENT_ID` | `benchmark-client` | Client ID with service-account access to the pod |
| `CLIENT_SECRET` | *(required)* | Client secret |
| `NR_OF_SENSORS` | `20` | Number of virtual sensors to generate |
| `RECORDS_PER_SENSOR` | `100000` | Measurements per sensor |
| `INSERT_BATCH_SIZE` | `10000` | Measurements per N-Triples file uploaded to S3 |
| `UPLOAD_WAVE_SIZE` | `20` | Files uploaded before waiting for auto-ingestion to commit them |
| `QUERY_ITERATIONS` | `5` | Times each benchmark query is repeated |
| `BENCHMARKS` | `slice` | Comma-separated benchmark names: `slice`, `time_range`, `single_id_lookup`, `latest_measurements`, or `all` |
| `TIME_RANGE_SECONDS` | `60` | Width of the queried time-window (seconds) |
| `STATE_FILE` | `benchmark_state.json` | File that `load_data.py` writes and `run_benchmarks.py` reads |

> **Tip — dev-services defaults**  
> When running against the Kvasir dev-services stack (`just dev-services-up` +
> `just dev`) use `KVASIR_BASE_URL=http://localhost:28080` and
> `KEYCLOAK_URL=http://localhost:28280`.

## Step 1 — Load data

```bash
python load_data.py
```

This script:
1. Obtains a bearer token via the Keycloak client-credentials flow.
2. Creates the pod if it does not yet exist.
3. Generates sensor metadata (small) and inserts it via the Changes API.
4. Streams measurement data as N-Triples files — one file per
   `INSERT_BATCH_SIZE` measurements — uploading each to
   `PUT /{podId}/s3/benchmark/batch_{n}.nt`.  Data is generated one batch at
   a time so memory usage stays constant regardless of total dataset size.
5. The server's **auto-rdf-ingest** feature detects each uploaded `.nt` file
   and automatically creates a change request.  The script polls
   `GET /{podId}/changes` in waves of `UPLOAD_WAVE_SIZE` files, checking
   `kss:associatedReferences` on each change report to detect when each S3
   key has been committed (or failed).
6. Writes a `benchmark_state.json` file containing the sensor IRIs and the
   data generation start-timestamp, so that `run_benchmarks.py` can derive
   the same time windows.

> **Prerequisite**: the benchmark pod must have `autoIngestRdf: true` in its
> configuration (set via `kss:configuration` when creating the pod, or by
> updating the pod config).  The `ensure_pod_exists` helper in the script
> creates a pod but does not yet set that flag automatically — set it once
> via the Pod Management API or bootstrap config.

## Step 2 — Run benchmarks

```bash
python run_benchmarks.py
```

Choose which benchmark suite(s) to run via `.env`:

```dotenv
BENCHMARKS=slice
# or
BENCHMARKS=time_range,single_id_lookup
# or
BENCHMARKS=latest_measurements
# or
BENCHMARKS=all
```

This script:
1. Reads `benchmark_state.json` (generated by `load_data.py`) **or**, if no
   state file is present, auto-discovers the sensor IRIs and infers the
   timestamp range by querying the live pod.
2. Runs three benchmark suites:
   - **Time-range query** — filters `saref_Measurement` by a
     `saref_hasTimestamp` window (25 % into the dataset, `TIME_RANGE_SECONDS`
     wide).
    - **Slice-backed time-range query** — ensures a dedicated slice with the
      benchmark SDL exists under `/{podId}/slices`, then runs the same query
      through `POST /{podId}/slices/{sliceId}/query`.
   - **Single-ID sensor lookup** — fetches each sensor individually by IRI.
    - **Latest measurements for one random sensor** — picks a random sensor
      from the discovered state and fetches its latest 50 measurements ordered
      by descending `saref_hasTimestamp`.
3. Prints a statistics table (min / avg / p95 / max) to stdout.

## Notes

- Both scripts authenticate via **client-credentials** (no user interaction
  needed, no DPoP required by default).
- The pod is **not** deleted after the benchmark so that you can iterate on
  `run_benchmarks.py` without re-loading.
- To reset data, delete the pod via `DELETE /{podName}` or recreate it.
- The `@filter` directive syntax (`it>='...';it<='...'`) matches what the
  Kvasir ClickHouse backend expects.
